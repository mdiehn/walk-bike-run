# Build and version

This project has a small repo-level build script because we want one clear command for producing the thing we deploy or install.

## Source of truth

`VERSION` is the source of truth for the app version.

Example:

```text
0.1.0-dev
```

Do not treat `src/version.js` as the source of truth. It is generated by `build.js`.

## Generated version module

The app imports:

```text
src/version.js
```

That file is generated from `VERSION` and currently looks like:

```js
export const APP_VERSION = '0.1.0-dev';
```

Run this to refresh it without building the full app:

```sh
npm run version:sync
```

## Build command

Use:

```sh
npm run build
```

That runs:

```sh
node build.js
```

The build script does three things:

1. reads `VERSION`
2. writes `src/version.js`
3. runs the Vite build
4. writes `dist/build-info.json`

## Build metadata

A production build writes:

```text
dist/build-info.json
```

That file records:

- app name
- app version
- build time
- Git branch, when available
- Git commit, when available
- whether the tree appeared dirty during the build

This is mainly for debugging update/deploy confusion later.

## Why not add a service worker yet?

Service workers are useful, but they can make update behavior confusing if they arrive before the release process is stable.

Do not add PWA caching until there is a clear update design and an obvious cache-clearing escape hatch.
